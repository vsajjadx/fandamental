# اتصال Fandamental به MetaTrader 5

این بخش سیگنال‌هایی را که **خود وب‌اپ** می‌سازد (`js/signal.js` → `FA.signal.analyze`) به متاتریدر ۵ منتقل می‌کند. منطق تحلیل، اندیکاتورها و AI دست‌نخورده‌اند؛ اکسپرت فقط سیگنال را می‌گیرد، کنترل‌های ریسک و ایمنی را انجام می‌دهد و نتیجه را گزارش می‌کند.

> ⚠️ هیچ سیستمی سود را تضمین نمی‌کند. «امتیاز هم‌سویی» احتمال سود نیست. حالت پیش‌فرض **فقط نمایش** است و معامله‌ی واقعی فقط با دو فعال‌سازی صریح و جداگانه (در وب‌اپ **و** در اکسپرت) انجام می‌شود. همه‌چیز را اول روی حساب **دمو** آزمایش کنید.

---

## ۱. معماری

```
 مرورگر (وب‌اپ فعلی)                 سرور پل (server/)                    MetaTrader 5
 ┌──────────────────────┐   HTTPS   ┌─────────────────────────┐   HTTPS   ┌──────────────────────────┐
 │ تحلیل + سیگنال (همان │──────────▶│ API + SQLite            │◀──────────│ FandamentalBridge.mq5    │
 │ موتور قبلی)          │ Bearer    │ کاربر/حساب/سیگنال/اجرا  │ X-Terminal│ WebRequest هر ۳ ثانیه    │
 │ تب جدید «MT5»        │ fa_u_…    │ ماشین وضعیت + لاگ ممیزی │ -Key      │ کنترل ریسک → OrderSend   │
 └──────────────────────┘           └─────────────────────────┘ fa_t_…    └──────────────────────────┘
```

- وب‌اپ قبلاً بک‌اند نداشت؛ یک بک‌اند کوچک Python در `server/` اضافه شد. وب‌اپ همچنان استاتیک است و روی GitHub Pages می‌ماند.
- اتصال همیشه از سمت MT5 شروع می‌شود (اکسپرت درخواست می‌دهد)، پس روی کامپیوتر/VPS متاتریدر پورتی باز نمی‌شود.
- دو نوع کلید جدا: **کلید وب‌اپ** `fa_u_…` (برای مدیریت و ارسال سیگنال) و **کلید ترمینال** `fa_t_…` (فقط برای یک اتصال MT5). سرور فقط هش SHA-256 کلیدها را نگه می‌دارد.

### چرا Starlette و نه FastAPI؟
FastAPI روی Starlette + Pydantic ساخته شده است. در محیط توسعه‌ی این تغییرات امکان نصب FastAPI نبود، پس API مستقیماً با **Starlette + Pydantic v2** نوشته شد تا بتوان آن را واقعاً تست کرد. وابستگی‌ها: `starlette`، `pydantic`، `uvicorn`.

## ۳. راه‌اندازی بک‌اند

سرور باید از **مرورگر شما** و از **کامپیوتر/VPS متاتریدر** قابل دسترس باشد و **HTTPS** داشته باشد (وب‌اپ روی GitHub Pages با HTTPS است و مرورگر درخواست HTTP را مسدود می‌کند).

### روش الف — Docker + HTTPS خودکار (پیشنهادی)

پیش‌نیاز: یک VPS لینوکسی با Docker، و یک دامنه یا زیردامنه که رکورد A آن به IP سرور اشاره کند.

```bash
git clone https://github.com/vsajjadx/fandamental.git
cd fandamental/server
cp .env.example .env
nano .env            # FA_DOMAIN و FA_ALLOWED_ORIGINS را تنظیم کنید
docker compose up -d --build
docker compose exec api python -m app.cli create-user "Sajjad"
#  → کلید API وب‌اپ (fa_u_…) فقط یک بار نمایش داده می‌شود؛ آن را در تب MT5 وب‌اپ وارد کنید
curl https://YOUR-DOMAIN/api/v1/health     # باید {"ok": true, ...} برگرداند
```

Caddy گواهی HTTPS را خودکار از Let's Encrypt می‌گیرد (پورت‌های ۸۰ و ۴۴۳ باید باز باشند).

### روش ب — بدون Docker

```bash
cd fandamental/server
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export FA_DB_PATH=$PWD/data/fandamental.db FA_ALLOWED_ORIGINS=https://vsajjadx.github.io FA_TRUST_PROXY=1
```

سپس Nginx/Caddy را با HTTPS جلوی پورت 8787 قرار دهید و برای اجرای دائمی یک سرویس systemd بسازید.

| متغیر | پیش‌فرض | توضیح |

| `FA_SENDING_TIMEOUT_SEC` | `120` | سفارشی که «در حال ارسال» ماند و نتیجه‌اش نرسید «نامشخص» می‌شود و **دوباره ارسال نمی‌شود** |
| `FA_RATE_LIMIT_PER_MIN` | `240` | سقف درخواست برای هر کلید |
| `FA_LOG_LEVEL` | `INFO` | سطح لاگ |

### migration
با هر بار اجرای سرور یا `python -m app.cli migrate`، فایل‌های جدید `app/migrations/*.sql` به ترتیب و فقط یک‌بار اجرا می‌شوند (ثبت در جدول `schema_migrations`). هیچ داده‌ای حذف نمی‌شود؛ اگر یک migration خطا بدهد کامل برگردانده می‌شود.

## ۴. تنظیم وب‌اپ

1. وب‌اپ را باز کنید → تب **MT5** (ستون راست).
2. «اتصال به سرور پل»: آدرس `https://YOUR-DOMAIN` و کلید `fa_u_…` → «ذخیره و آزمایش اتصال».
3. «ساخت اتصال جدید» → کلید ترمینال `fa_t_…` **فقط یک‌بار** نشان داده می‌شود؛ کپی کنید.
4. حالت اتصال به‌صورت پیش‌فرض «فقط نمایش سیگنال» است.

بعد از هر «تحلیل کن»، زیر کادر سیگنال دکمه‌ی **«ارسال این سیگنال به MT5»** ظاهر می‌شود. گزینه‌ی «ارسال خودکار سیگنال‌های معتبر» فقط سیگنال‌هایی را می‌فرستد که موتور فعلی `tradeable` اعلام کرده است. ارسال دوباره‌ی همان تحلیل (همان کندل) سفارش تکراری نمی‌سازد.

## ۵. نصب و کامپایل اکسپرت در متاتریدر ۵

1. در MT5: **File → Open Data Folder** → پوشه‌ی `MQL5\Experts` را باز کنید.
2. فایل `mt5/FandamentalBridge.mq5` را آنجا کپی کنید.
3. **MetaEditor** را باز کنید (F4) → در Navigator روی `FandamentalBridge.mq5` دابل‌کلیک → **Compile** (F7). باید `0 errors` ببینید و فایل `FandamentalBridge.ex5` ساخته شود. اگر خطایی دیدید، متن کامل آن را برای من بفرستید.
4. **مجاز کردن آدرس سرور برای WebRequest:** در MT5 → **Tools → Options → Expert Advisors** → تیک **Allow WebRequest for listed URL** → آدرس `https://YOUR-DOMAIN` را اضافه کنید (دقیقاً همان آدرسی که در ورودی اکسپرت می‌گذارید، بدون مسیر). بدون این مرحله خطای 4014 در تب Experts می‌بینید.
5. در همان پنجره «Allow algorithmic trading» را فعال کنید و دکمه‌ی **Algo Trading** نوار ابزار را روشن کنید (برای حالت نمایش لازم نیست، برای اجرای سفارش لازم است).
6. اکسپرت را روی **یک** چارت بکشید (هر نمادی؛ بهتر است همان نمادی که بیشتر سیگنال می‌گیرید تا خطوط ورود/SL/TP روی آن رسم شود). در تب Common گزینه‌ی «Allow Algo Trading» را تیک بزنید و در تب Inputs:

| ورودی | مقدار پیشنهادی | توضیح |
|---|---|---|
| `InpServerUrl` | `https://YOUR-DOMAIN` | آدرس پایه‌ی سرور |
| `InpTerminalKey` | `fa_t_…` | کلید ترمینال از تب MT5 |
| `InpPollSeconds` | `3` | فاصله‌ی دریافت سیگنال |
| `InpExecutionEnabled` | `true` | کلید قطع محلی؛ `false` = هرگز سفارش نده |
| `InpAllowRealAccount` | **`false`** | فقط وقتی آگاهانه می‌خواهید روی حساب واقعی معامله شود `true` کنید |
| `InpMagic` | `26101701` | شماره‌ی شناسایی سفارش‌های این اکسپرت |
| `InpSlippagePoints` | `20` | حداکثر لغزش قیمت سفارش بازار |
| `InpSymbolSuffix` | خالی | پسوند نماد بروکر (مثلاً `.m`)؛ تنظیم وب‌اپ هم امتحان می‌شود |
| `InpShowAlerts` / `InpPushNotifications` | `true` / `false` | هشدار پاپ‌آپ / ارسال به موبایل MT5 |
| `InpDrawLevels` | `true` | رسم خطوط ورود/SL/TP روی چارت هم‌نماد |
| `InpTimeoutMs` | `7000` | مهلت هر درخواست HTTP |
| `InpMaxQuoteAgeSec` | `300` | روی قیمت قدیمی‌تر از این (بازار بسته) معامله نکن |

7. بالای چارت پنل وضعیت ظاهر می‌شود (`Server: connected`). در وب‌اپ، کارت اتصال باید «● متصل» و شماره‌ی حساب و دمو/واقعی را نشان دهد.

> اکسپرت در **Strategy Tester** اجرا نمی‌شود، چون MT5 در تستر اجازه‌ی WebRequest نمی‌دهد. روی چارت حساب دمو اجرا کنید.

### تطبیق نماد
ترتیب جستجو: ۱) «نگاشت نماد» در وب‌اپ (مثلاً `{"SPX":"US500","BTCUSDT":"BTCUSD"}`) ۲) نماد + پسوند وب‌اپ ۳) نماد + `InpSymbolSuffix` ۴) خود نماد ۵) نام‌های رایج (`XAUUSD→GOLD`، `SPX→US500/SPX500`، `NDX→US100/NAS100/USTEC`، `DJI→US30`، `USOIL→WTI/XTIUSD`، `…USDT→…USD`) ۶) نزدیک‌ترین نماد بروکر که با همین نام شروع شود (`EURUSDm`، `XAUUSD.pro`). اگر پیدا نشود سیگنال با علت «symbol not found» رد می‌شود. نمادهای بورس تهران در MT5 قابل معامله نیستند و ارسال نمی‌شوند.

## ۶. سه حالت اجرا

| حالت | رفتار |
|---|---|
| **فقط نمایش** (پیش‌فرض) | هشدار + خطوط روی چارت؛ هیچ سفارشی ثبت نمی‌شود |
| **اجرا پس از تأیید من** | سیگنال در تب MT5 «منتظر تأیید شما» می‌ماند؛ با «تأیید» به اکسپرت تحویل و اجرا می‌شود؛ با «رد» لغو می‌شود. تأیید بعد از انقضای سیگنال ممکن نیست |
| **اجرای خودکار** | اکسپرت بعد از همه‌ی کنترل‌ها سفارش ثبت می‌کند |

روی **حساب واقعی** در هر دو حالت اجرایی، سفارش فقط وقتی ثبت می‌شود که هم در وب‌اپ «فعال‌سازی معامله‌ی واقعی» (با تایپ عبارت `ENABLE LIVE <شماره‌ی حساب>`) انجام شده باشد و هم در اکسپرت `InpAllowRealAccount=true` باشد. سرور نوع حساب را از خود اکسپرت می‌گیرد و هر دو شرط را لحظه‌ی ارسال دوباره بررسی می‌کند.

### چرخه‌ی وضعیت هر سیگنال برای هر حساب

```
awaiting_approval ─تأیید→ approved ─┐
pending ────────────────────────────┴→ delivered → sending → filled | placed | failed | unknown
                                          │                      (unknown → تطبیق با بروکر → filled/failed)
                                          └→ displayed (حالت نمایش) | rejected (کنترل‌ها)
هر وضعیت قبل از sending ممکن است → expired (انقضا) | cancelled (لغو توسط شما)
```
علت هر رد/خطا در ستون «وضعیت» جدول تب MT5 نمایش داده می‌شود و در لاگ ممیزی (`GET /api/v1/audit`) ثبت است.

## ۷. کنترل‌های قبل از ثبت سفارش (در اکسپرت)

- اعتبار و تازگی: سیگنال منقضی رد می‌شود؛ سرور لحظه‌ی ارسال با ساعت خودش دوباره بررسی می‌کند (اختلاف ساعت کامپیوتر مهم نیست).
- وضعیت حساب: اتصال ترمینال به بروکر، دکمه‌ی Algo Trading، مجوز معامله‌ی حساب (رمز Investor رد می‌شود)، مجوز اکسپرت از طرف بروکر، دمو/واقعی.
- حد ضرر و حد سود: جهت درست، فاصله از Stops Level بروکر؛ اگر قیمت از SL یا TP عبور کرده باشد رد می‌شود. سطوح سیگنال بی‌صدا تغییر داده نمی‌شوند.
- حجم و ریسک: حجم = (درصد ریسک × min(موجودی، اکوئیتی)) ÷ زیان یک لات تا حد ضرر (`OrderCalcProfit`)، سپس سقف «حداکثر لات»، گرد کردن به گام حجم بروکر؛ اگر کمتر از حداقل حجم بروکر شود رد می‌شود (حجم بالا برده نمی‌شود). یا لات ثابت.
- اسپرد: سقف پوینتی و/یا سقف نسبت به فاصله‌ی حد ضرر.
- فاصله‌ی قیمت از نقطه‌ی ورود: اگر قیمت بیش از درصد تعیین‌شده‌ی فاصله‌ی حد ضرر از ورود دور شده باشد رد می‌شود.
- سفارش تکراری: جستجوی برچسب `FA:<شناسه>` در پوزیشن‌ها، سفارش‌ها و تاریخچه‌ی ۳۰ روز؛ پوزیشن/سفارش باز Fandamental روی همان نماد؛ در حساب Netting هر پوزیشن روی همان نماد.
- حداکثر پوزیشن هم‌زمان و حد ضرر روزانه (سود/زیان بسته‌شده‌ی امروز + شناور پوزیشن‌های اکسپرت).
- محدودیت‌های نماد و بروکر: مجاز بودن جهت معامله، تازگی قیمت، پشتیبانی از انقضای سفارش برای لیمیت، نوع پرشدن سفارش (FOK/IOC/RETURN با `OrderCheck`)، `OrderCheck` نهایی (مارجین و …).
- ثبت نتیجه: قیمت درخواستی، قیمت اجرای واقعی، لغزش، حجم، تیکت، کد بروکر؛ بعداً قیمت بسته شدن، سود/زیان و علت (SL/TP/دستی/Stop-out).

## ۸. جلوگیری از سفارش تکراری و مدیریت قطعی

1. هر سیگنال برای هر حساب فقط یک ردیف اجرا دارد؛ ارسال دوباره‌ی همان سیگنال از وب‌اپ کاری نمی‌کند.
2. اکسپرت **قبل از** `OrderSend` وضعیت `sending` را گزارش می‌کند و تا پاسخ «go» سرور را نگیرد سفارش نمی‌دهد. سرور فقط یک‌بار go می‌دهد و از آن به بعد آن سیگنال را دوباره تحویل نمی‌دهد.
3. اگر پاسخ go در شبکه گم شود، اکسپرت سفارش نمی‌دهد؛ سرور بعد از `FA_SENDING_TIMEOUT_SEC` آن را «نامشخص» می‌کند و اکسپرت با جستجوی برچسب در بروکر تطبیق می‌دهد (پیدا نشد → «خطا»، **ارسال مجدد نمی‌شود**).
4. اگر نتیجه‌ی سفارش ارسال نشود (قطعی شبکه/ری‌استارت MT5)، گزارش در فایل `MQL5\Files\FandamentalBridge\queue.txt` می‌ماند و تا تأیید سرور با همان شناسه تکرار می‌شود (تکرار بی‌اثر است).
5. خطاهای موقت (قطعی، 429، 5xx) با تأخیر افزایشی تکرار می‌شوند؛ requote/price changed حداکثر دو بار با قیمت تازه و کنترل مجدد فاصله.
6. اگر بروکر timeout بدهد، وضعیت «نامشخص» گزارش و تطبیق می‌شود — هرگز کورکورانه دوباره ارسال نمی‌شود.

## ۹. امنیت

- رمز و اطلاعات ورود حساب معاملاتی **هیچ‌جا** لازم نیست و ذخیره نمی‌شود؛ اکسپرت داخل ترمینال خودتان اجرا می‌شود.
- HTTPS اجباری (به‌جز localhost)، CORS فقط برای آدرس وب‌اپ، سقف حجم درخواست و محدودیت نرخ.
- کلیدها فقط به‌صورت هش در دیتابیس؛ کلید ترمینال فقط یک‌بار نمایش داده می‌شود و قابل تعویض است. کلید ترمینال به اولین حساب MT5ای که وصل شود قفل می‌شود (استفاده در حساب دیگر رد می‌شود تا «جداکردن حساب»).
- هر کاربر فقط حساب‌ها، سیگنال‌ها و اجراهای خودش را می‌بیند (درخواست به منبع کاربر دیگر = 404).
- لاگ‌ها و لاگ ممیزی هیچ کلیدی ندارند (فیلتر حذف کلید روی همه‌ی لاگ‌ها).
- کلید وب‌اپ مثل سایر کلیدهای فعلی اپ در `localStorage` مرورگر خودتان ذخیره می‌شود؛ روی دستگاه عمومی ذخیره نکنید.

## ۱۰. مرجع API

وب‌اپ — هدر `Authorization: Bearer fa_u_…`

| متد | مسیر | کار |
|---|---|---|
| GET | `/api/v1/health` | سلامت (بدون کلید) |
| GET | `/api/v1/me` | کاربر فعلی |
| POST | `/api/v1/signals` | ثبت سیگنال (تکرار `client_signal_id` = بدون اثر) |
| GET | `/api/v1/signals`، `/api/v1/signals/{id}` | فهرست/جزئیات با وضعیت اجرا در هر حساب |
| POST | `/api/v1/signals/{id}/cancel` | لغو |
| GET/POST | `/api/v1/accounts` | فهرست/ساخت اتصال (کلید ترمینال یک‌بار) |
| GET/PATCH | `/api/v1/accounts/{id}` | جزئیات/تنظیمات (حالت، فعال، ریسک، نماد) |
| POST | `/api/v1/accounts/{id}/rotate-key` | کلید ترمینال جدید |
| POST | `/api/v1/accounts/{id}/live` | `{"enable":true,"confirm":"ENABLE LIVE <login>"}` |
| POST | `/api/v1/accounts/{id}/reset-binding` | جدا کردن حساب MT5 |
| GET | `/api/v1/executions?account_id=&state=` | گزارش اجراها |
| POST | `/api/v1/executions/{id}/approve` ، `/reject` | تأیید/رد دستی |
| GET | `/api/v1/audit` | لاگ ممیزی |

اکسپرت — هدر `X-Terminal-Key: fa_t_…`

| متد | مسیر | کار |
|---|---|---|
| POST | `/api/v1/ea/heartbeat` | معرفی حساب (login، سرور، دمو/واقعی، موجودی) و دریافت تنظیمات |
| GET | `/api/v1/ea/pending` | کارهای جدید + موارد نیازمند تطبیق + پوزیشن‌های باز برای پیگیری |

| POST | `/api/v1/ea/executions/{id}/closed` | نتیجه‌ی نهایی پوزیشن |

**آزمایش‌نشده (باید شما انجام دهید):**
- **کامپایل اکسپرت در MetaEditor و اجرای آن در MT5 واقعی** — در محیط توسعه MetaTrader در دسترس نبود. کد با دقت بازبینی شده و پروتکل آن با شبیه‌ساز تست شده، اما تا وقتی روی حساب دمو اجرا نکرده‌اید آن را تأییدشده ندانید.
- **ساخت image داکر و Caddy** — داکر در محیط توسعه اجرا نمی‌شد؛ خود سرور با همان دستور uvicorn پشت پراکسی HTTPS تست شد.

### چک‌لیست تست روی حساب دمو (به ترتیب)
1. کامپایل بدون خطا (F7).
2. حالت «فقط نمایش»: «تحلیل کن» → «ارسال به MT5» → در MT5 هشدار و خطوط؛ وضعیت در وب‌اپ «نمایش داده شد».
3. نماد با پسوند بروکر (مثلاً `EURUSD.m`) درست پیدا شود؛ در غیر این صورت پسوند یا نگاشت نماد را تنظیم کنید.
4. حالت «اجرا پس از تأیید» روی دمو: تأیید → سفارش با حجم کوچک، SL و TP درست؛ قیمت اجرا و تیکت در وب‌اپ.
5. ارسال دوباره‌ی همان سیگنال → پیام «قبلاً ارسال شده»، بدون سفارش دوم.
6. سیگنال با اعتبار کوتاه (تایم‌فریم 5m) را دیر تأیید کنید → «منقضی شد».
7. قطع اینترنت MT5 چند دقیقه و وصل مجدد → وضعیت «قطع/متصل» و ارسال گزارش‌های معوق، بدون سفارش تکراری.
8. حد ریسک: «حداکثر لات» را کوچک کنید و ببینید حجم محدود شود؛ اسپرد را سخت‌گیرانه کنید و ببینید رد شود.
9. بستن پوزیشن با TP/SL/دستی → سود/زیان و علت در جدول.
10. «اجرای خودکار» روی دمو حداقل چند روز، و مقایسه‌ی نتیجه با تب «بک‌تست» و «ژورنال».

فقط بعد از این مراحل و آگاهانه، معامله‌ی واقعی را جداگانه فعال کنید.

## ۱۲. محدودیت‌ها و نکات صادقانه

- این ابزار **سودآوری را تضمین نمی‌کند**؛ فقط سیگنال‌های همان موتور فعلی را با کنترل ریسک اجرا می‌کند. کیفیت نتیجه به کیفیت سیگنال‌ها بستگی دارد که باید با بک‌تست و Paper Trading سنجیده شود.
- طراحی برای حساب‌های **Hedging** است؛ در Netting اگر روی همان نماد پوزیشن باشد، سیگنال رد می‌شود.
- تشخیص تکراری و تطبیق بر پایه‌ی comment سفارش (`FA:…`) است؛ برخی بروکرها comment را تغییر می‌دهند. در آن صورت دو لایه‌ی دیگر (سرور + «پوزیشن باز روی همین نماد») همچنان مانع تکرار می‌شوند.
- اکسپرت هر ۳ ثانیه پیام می‌گیرد؛ برای سیگنال‌های تایم‌فریم ۵ دقیقه به بالا کافی است، نه برای اسکالپ ثانیه‌ای.
- حجم فارکس در منابع رایگان وب‌اپ واقعی نیست (محدودیت قبلی وب‌اپ)؛ این بخش در پل تغییری نکرده است.
- اگر MT5 یا سرور شما پشت فیلترینگ است، سرور را جایی میزبانی کنید که هم از مرورگر و هم از کامپیوتر/VPS متاتریدر بدون VPN باز شود.
